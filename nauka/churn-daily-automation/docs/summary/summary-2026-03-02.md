### **1. Naprawa błędu: Brakujące linie w tabeli PLK** ✅

**Problem:**

- W mailu PLK czasami brakuje jednej lub kilku linii (np. MIX)
- Stary kod: `.values[0]` → **crash** (IndexError)
- System przestawał działać przy braku danych

**Rozwiązanie:**

- Nowa funkcja `get_wartosc_plk(df, linia_nazwa)`
- Zwraca wartość jeśli istnieje, `None` jeśli brakuje
- Komunikat: "UWAGA: Brak linii X w PLK!"
- W bazie zapisują się tylko produkty które istnieją

**Kod:**

```python
def get_wartosc_plk(df, linia_nazwa):
    wynik = df.loc[df['Linia'] == linia_nazwa, 'Wykonanie']
    if len(wynik) > 0:
        return wynik.values[0]
    else:
        print(f"UWAGA: Brak linii {linia_nazwa} w PLK!")
        return None
```

**W `zapisz_do_bazy()`:**

```python
if dane_plk is not None:
    biz, data, data_ftth, ind, mix = dane_plk
    
    if biz is not None:
        dane.append((dzis, 'PLK', 'BIZ', int(biz), miesiac))
    if data is not None:
        dane.append((dzis, 'PLK', 'DATA', int(data), miesiac))
    # ... itd dla każdego produktu
```

**Wynik testu:**

```
UWAGA: Brak linii MIX w PLK!
Wstawiono: 4, Zaktualizowano: 2
```

✅ 4 produkty PLK zapisane (bez MIX), system nie crashuje!

### **2. Naprawa logiki INSERT vs UPDATE (UPSERT)** ✅

**Problem:**

- Marzec miał już 2 wiersze (CP: TV, IN)
- Skrypt sprawdzał: "czy miesiąc 202603 istnieje?" → TAK
- Robił UPDATE dla wszystkich produktów
- UPDATE dla PLK nie działał (bo PLK nie miał jeszcze wierszy dla marca)
- PLK się **nie zapisywał do bazy!**

**Stara logika (ZŁA):**

```python
if miesiąc_istnieje:
    UPDATE wszystko  # ← Ale PLK nie ma wierszy, więc UPDATE nie działa!
else:
    INSERT wszystko
```

**Nowa logika (DOBRA) - UPSERT:**

```python
for każdy_wiersz in dane:
    if produkt_istnieje_dla_tego_miesiąca:
        UPDATE
    else:
        INSERT
```

**Implementacja:**

```python
inserted = 0
updated = 0

for row in dane:
    data_raportu, spolka, produkt, wartosc, miesiac = row
    
    # Sprawdź czy TEN KONKRETNY produkt istnieje
    query_check = f"""
        SELECT COUNT(*) FROM db_work_dwn.Churn_Daily 
        WHERE SPOLKA = '{spolka}' 
        AND PRODUKT = '{produkt}' 
        AND MIESIAC = '{miesiac}'
    """
    cursor.execute(query_check)
    exists = cursor.fetchone()[0]
    
    if exists == 0:
        # INSERT - produktu nie ma
        insert_sql = "INSERT INTO db_work_dwn.Churn_Daily VALUES (?,?,?,?,?)"
        cursor.execute(insert_sql, row)
        inserted += 1
    else:
        # UPDATE - produkt istnieje
        update_sql = """
            UPDATE db_work_dwn.Churn_Daily 
            SET WARTOSC = ?, DATA_RAPORTU = ?
            WHERE SPOLKA = ? AND PRODUKT = ? AND MIESIAC = ?
        """
        cursor.execute(update_sql, (wartosc, data_raportu, spolka, produkt, miesiac))
        updated += 1

print(f"\nWstawiono: {inserted}, Zaktualizowano: {updated}")
```

**Wynik testu:**

```
Wstawiono: 4, Zaktualizowano: 2
```

✅ PLK poprawnie zapisany! (4 nowe wiersze + 2 updated CP)

## 💡 **KLUCZOWE INSIGHT:**

**Problem był subtelny:**

- Sprawdzanie "czy miesiąc istnieje" zamiast "czy produkt istnieje"
- To typowy przypadek gdzie **granularność sprawdzania** jest kluczowa
- Rozwiązanie: sprawdzaj na najniższym poziomie (produkt + miesiąc)

**Lesson learned:**
> Warunki biznesowe powinny być sprawdzane na poziomie który faktycznie się zmienia, nie na poziomie agregatu!
